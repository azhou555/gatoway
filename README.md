# gatoway

Cost-aware LLM gateway (MVP). Routes each request to the cheapest model tier
likely to produce an acceptable result, using embedding-similarity matching
against a growing bank of past requests plus session-level difficulty
signals — instead of static per-request rules.

Full architecture: `SPEC.md`. Subtask breakdown: `TASKS.md`.

## Status

MVP is implemented end-to-end and passing 44/44 tests: gateway API, router
(embedding similarity + session-aware threshold shifting), circuit breaker
with provider fallback, batch feedback job, seed data, and an eval harness
that produces the cost/effectiveness report below.

Cut from v0.1 (see `TASKS.md` for the full list and why): OpenTelemetry /
Prometheus / Grafana, Redis-backed session state, the Ollama local tier
(config stub only, not wired into the router by default), ML-based keyword
extraction, and a real LLM-judge (heuristic stub instead).

## Getting started

```bash
# 1. Start Postgres (pgvector)
cp .env.example .env
docker compose up -d

# 2. Install deps
pip install -e ".[dev]"

# 3. Run the schema migration
python -m gatoway.db migrate

# 4. Seed the embedding bank (cold start — see SPEC.md §8)
python -m gatoway.seed

# 4b. (optional) Grow the bank with your own difficulty labels, no LLM needed
python -m gatoway.label_seed

# 5. Run tests
pytest

# 5b. Check gateway-added latency against SPEC.md §9's <=100ms budget
python -m gatoway.bench_latency

# 6. Run the gateway API
uvicorn gatoway.app:app --reload
# or: python -m gatoway.main
```

The gateway exposes an OpenAI-compatible `POST /v1/chat/completions`:

```bash
curl -X POST http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "what is 2+2?"}]}'
```

The response includes the usual OpenAI `choices`/`usage` shape plus a
`gatoway` metadata block reporting which tier/model was actually used,
routing confidence, cost, and whether the classifier fallback path fired.

## Benchmarks

`python -m gatoway.eval` runs 8 hand-written benchmark tasks (exact-match
and heuristic-judge scoring, per SPEC.md §8) through the live router versus
an "always frontier tier" baseline. Full methodology, caveats, and current
numbers: `eval_report.md` (regenerated by every eval run). Current headline:

**71% compute-proxy reduction, -3 point effectiveness delta vs always
routing to the frontier tier.**

| Task | Router Tier | Router Score | Baseline Score |
|---|---|---|---|
| capital_france | cheap | 1.00 | 1.00 |
| arithmetic | cheap | 1.00 | 1.00 |
| unit_conversion | cheap | 1.00 | 1.00 |
| quadratic_roots | medium | 1.00 | 1.00 |
| code_fix | medium | 0.75 | 0.89 |
| sql_query | medium | 0.65 | 0.79 |
| multistep_planning | frontier | 1.00 | 1.00 |
| hard_math_proof | frontier | 0.88 | 0.88 |

Two important caveats, spelled out in full in `eval_report.md`:

- **No API keys needed to run this.** `--dry-run` (auto-selected when no
  `ANTHROPIC_API_KEY`/`OPENAI_API_KEY` is set) uses hand-authored canned
  responses per tier instead of real provider calls, and the "cost" column
  is a **parameter-count proxy**, not real spend — real figures for local
  Ollama tiers (queried from a running Ollama server), order-of-magnitude
  estimates for hosted tiers whose param counts Anthropic doesn't publish.
  Run without `--dry-run` (with real API keys set) for a report against
  actual provider cost and model output.
- **The router does hit the live `decision_history` bank for real** — tier
  decisions above came from real pgvector nearest-neighbor queries against
  the seed bank (`gatoway/seed.py`), not from the tasks' own hand-labeled
  difficulty. This matters: an earlier version of this bank had an ivfflat
  ANN index with default `lists` tuning that was badly oversized for a
  24-row bank (each cluster held ~0-1 vectors, so the default `probes=1`
  missed the true nearest neighbor and misrouted several tasks) — dropping
  that index in favor of an exact sequential scan (see `schema.sql`) moved
  the effectiveness delta from -13pt to -3pt. Re-add a properly-tuned
  ivfflat/hnsw index only once the bank is large enough that a seq scan is
  a measured bottleneck.

## Latency

`python -m gatoway.bench_latency` measures SPEC.md §9's actual deliverable —
"≤100ms added by the gateway on top of native provider latency" — by running
real requests through the full pipeline (real embedding model, live
Postgres session tracking + router query + decision_history write) with only
the provider network call itself stubbed out (explicitly excluded from this
budget by SPEC.md §9, and stubbing it keeps the benchmark free to run).
Current result: **p50 26ms, p95 34ms — comfortably under the 100ms target.**

## Layout

- `docker-compose.yml` — Postgres w/ pgvector extension.
- `schema.sql` — `spend_ledger`, `sessions`, `decision_history` tables.
- `gatoway/db.py` — asyncpg connection pool + `migrate()`.
- `gatoway/embeddings.py` — local sentence-transformers embedding (384-dim,
  no API key needed).
- `gatoway/router.py` — classifier: nearest-neighbor tier decision +
  confidence-floor fallback + session-threshold shifting.
- `gatoway/session.py` — session boundary detection, threshold shifting.
- `gatoway/providers.py` — litellm-backed provider adapter per tier.
- `gatoway/circuit_breaker.py` — provider retry/fallback + cooldown state
  machine.
- `gatoway/app.py` — FastAPI gateway wiring the above together.
- `gatoway/seed.py` — cold-start embedding bank seed data.
- `gatoway/label_seed.py` — interactive CLI to grow the bank with your own
  difficulty labels (no LLM calls needed).
- `gatoway/batch_job.py` — end-of-session quality scoring + bank write-back
  (train-split only).
- `gatoway/eval.py` — benchmark harness, produces `eval_report.md`.
- `gatoway/bench_latency.py` — gateway-overhead latency benchmark (SPEC.md §9).
- `tests/` — 44 tests covering router, session, circuit breaker, batch job,
  and the gateway API.
