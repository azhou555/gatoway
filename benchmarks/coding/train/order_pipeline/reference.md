Orders owns the order state machine, inventory owns reservations, payments owns charges, and shipping owns fulfillment. Commit each state transition with an outbox entry in one database transaction; a relay publishes events at least once. Consumers record processed event IDs transactionally with their own state changes and use idempotency keys for payment calls. Partition events by order ID and check monotonic versions to reject stale transitions. A saga reserves stock before charging and ships only after payment confirmation; failures release reservations or refund a captured payment. Retry transient failures with backoff, move persistent errors to a dead-letter queue, and expose per-order traces plus an operator reconciliation workflow.
