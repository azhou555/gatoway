1) Extract one bounded context at a time behind a strangler facade. Keep old API contracts compatible and start with a small percentage of traffic while the monolith handles the rest.
2) Backfill the service's own store. Commit each business change and its outbox event in the same transaction in the original database; an idempotent consumer applies that event to the new store. This avoids a non-atomic write to two databases. Before switching reads or write ownership, compare record counts, checksums, and business invariants, reconcile differences, and wait for replication lag to reach zero.
3) Shadow requests and then increase traffic gradually behind a feature flag. Keep one authoritative writer throughout each phase. If validation or error-rate gates fail, turn the flag back to the monolith; retain the old store and keep it synchronized during the rollback window so reverting does not lose accepted writes. Complete the ownership transfer only after the validation gates pass.
